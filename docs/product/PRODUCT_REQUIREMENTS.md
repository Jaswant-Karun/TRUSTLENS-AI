# TRUSTLENS AI — CORE PRODUCT MODULE REQUIREMENTS

---

| Module | User Problem Solved | Inputs / Outputs | Existing Implementation | Required Changes | Acceptance Criteria |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **A. Fraud Analysis Engine** | Classify untrusted text, URLs, screenshots | In: text, URL, image; Out: `AnalysisResultResponse` | `analyze.py`, `analysis_service.py`, `ocr_service.py`, `CentralModelLoader` | Improve Hindi recall & URL FPR in future ML phase | Valid submissions hit live ML models; unavailable models return explicit status |
| **B. Evidence & Explanation Engine** | Explain *why* content is suspicious | In: model outputs, SHAP, IOCs; Out: `transparency_breakdown`, `remedial_actions` | `risk_service.py`, `ml/explainability/explainer.py`, `AnalysisResultPanel.tsx` | Keep strict separation of ML vs TI vs Human | Every verdict lists model version, evidence, and uncertainty/limitations |
| **C. Investigation & Case Management** | Connect indicators into persistent cases | In: case metadata, node IDs; Out: graph, timeline, 1-hop neighbors | `investigations.py`, `investigation_service.py`, `InvestigationWorkspace.tsx` | Add auth guard on `POST /investigations`, notes endpoint, and timeline population | Saved cases persist across restarts; 1-hop queries return real DB links |
| **D. Threat Indicator Intelligence** | Search & inspect known IOCs with provenance | In: search, facets, sort; Out: paginated `ThreatLibraryItem`s | `threat_library.py`, `threat_library_service.py`, `threat-library/page.tsx` | Done (`indicator_type_1_indicator_value_1` index fixed in Phase 0.5) | Empty queries show empty state; every row shows provenance & verification |
| **E. Similarity & Campaign Discovery** | Group recurring lure patterns | In: message embedding; Out: cluster ID, cohesion, shared IOCs | `campaigns.py`, `campaign_service.py`, `ml/campaign_detection/*` | Sync `campaign_dossiers.json` into MongoDB `scam_campaigns` | Explicitly labeled as similarity candidates, never legal attribution |
| **F. Community Reporting & Review** | Crowdsource & human-verify scams | In: report payload, review verdict; Out: `ReportResponse`, `threat_indicators` | `reports.py`, `report_service.py`, `reports/page.tsx` | Add `request_more_info` status if desired | Non-analysts receive `403` on review; decisions create `audit_logs` |
| **G. Analysis History & Saved Cases** | Revisit past scans & outcomes | In: user JWT, filters; Out: paginated `analyses` | `analyses.py`, `history/page.tsx` | Allow attaching a saved analysis directly to an investigation | Users see own scans only; analysts see all |
| **H. Notifications & Alerts** | Alert SOC on high-risk scans/feeds | In: `analysis_id`, cluster; Out: redacted alert + `automation_logs` | `automation.py`, `automation_service.py`, `n8n/workflows/02_*.json` | Connect live n8n instance when hosted | Duplicate alerts suppressed; raw message text redacted |
| **I. Export & Reporting** | Share auditable findings | In: `report_type`, `target_id`; Out: structured report, JSON, STIX 2.1 | `exports.py`, `reporting_service.py`, `IntelligenceReportPanel.tsx` | None (5 report types + STIX 2.1 verified) | STIX 2.1 bundles contain only supported SDOs/SCOs/SROs |
| **J. User, Org & Permission Mgmt** | Authenticate & enforce RBAC | In: credentials, JWT; Out: `UserProfile`, `access_token` | `auth.py`, `auth_service.py`, `dependencies.py` | Add user/role admin endpoints if multi-org is required | Invalid JWT -> `401`; unauthorized role -> `403` |
